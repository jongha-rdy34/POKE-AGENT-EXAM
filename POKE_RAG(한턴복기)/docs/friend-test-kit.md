# 친구 테스트 준비 자료

작성 2026-10-23 · 근거: 설계 The Assignment·전제 5, CEO 리뷰 C8-1(기록)·C-O3(진짜 패인 질문)·C-O6(판정 규칙)·C3-1(초대 토큰), 디자인 재리뷰 #2(DR20~DR22).

이 테스트로 확인하는 것은 세 가지다.
1. **전제 5:** "의문의 패배"는 정보가 없어서 생기고, 원인을 알면 계속하고 싶어지는가.
2. **복기가 쓸모 있는가:** 친구가 결과를 본 뒤 원인 후보와 다음 행동을 **자기 말로** 설명할 수 있는가.
3. **자연어 입력이 통하는가:** 친구가 쓴 문장을 앱이 제대로 알아듣는가(확인 단계에서 몇 번 고쳤는가).

진행은 두 단계로 나뉜다.
- **1단계(지금, 앱 없이):** 친구 3명에게서 납득 안 된 한 턴을 받아 적는다.
- **2단계(앱이 생긴 뒤):** 같은 친구가 직접 앱에 입력하고 결과를 본다.

---

## 1단계 — 사례 수집 (지금)

### 친구에게 보낼 메시지

> 포켓몬 챔피언스 랭크배틀 하다가 "이게 왜 졌지?" 싶었던 한 턴이 있으면 알려 줄 수 있어?
> 패배 직후 그 한 턴을 넣으면 원인을 찾아 주는 걸 만들고 있어서, 실제 사례가 필요해.
> 5분이면 되고, 기억나는 만큼만 말해 주면 돼. 정확하지 않아도 괜찮아.
> 나중에 앱이 생기면 그 턴을 직접 넣어 보는 것도 부탁할게.

### 받아 적는 방법

- **질문 순서를 지킨다.** 친구의 원래 말(③)을 **먼저** 받고 나서 세부(④~⑧)를 묻는다. 세부를 먼저 물으면 친구의 표현이 바뀌어, 자연어 입력 평가 재료가 오염된다.
- **고쳐 주지 않는다.** 친구가 틀린 용어를 써도 그대로 적는다. 원인을 설명해 주지도 않는다. 설명하면 2단계에서 "자기 말로 설명"을 잴 수 없다.
- 기억나지 않으면 "모름"이라고 적는다. 추측해서 채우지 않는다.

### 사례 기록지 (친구 1명당 1장)

| # | 질문 | 적는 방식 | 답 |
|---|---|---|---|
| ① | 친구 구분(1·2·3) | 이름 대신 번호 | |
| ② | 언제였나요? | 날짜, 시즌(M-6/M-7), 싱글/더블 | |
| ③ | **무슨 일이 있었는지 한 줄로 말해 줘** | **원래 말 그대로.** 2단계에서 앱에 넣을 문장의 기준 | |
| ④ | 왜 졌다고 생각했어? | **원래 말 그대로** | |
| ⑤ | 내 포켓몬 / 상대 포켓몬 | 메가 여부 포함, 모르면 "모름" | |
| ⑥ | 누가 누구에게 어떤 기술을 썼어? | 공격한 쪽 + 기술 이름 | |
| ⑦ | 결과가 어땠어? | 한 방에 쓰러짐 / 버팀(남은 HP 대략) / 상대가 먼저 움직임 / 내가 먼저 움직임 | |
| ⑧ | 그 턴에 있었던 것 (기억나는 것만) | 급소·화상·능력 변화·테라스탈·날씨·필드·리플렉터·빛의장막·트릭룸·순풍 | |
| ⑨ | 내 포켓몬 빌드를 알아? | 도구·성격·SP(예: A32 S32). 모르면 "모름" | |
| ⑩ | 원래 어떻게 될 줄 알았어? | 예상했던 결과 | |
| ⑪ | 그 턴이 그 판을 진 진짜 이유였어? | 예 / 아니요 / 모르겠어요 + 한마디 | |
| ⑫ | 그다음에 뭘 했어? | 원인을 찾아봤다(어디서, 얼마나) / 그냥 다음 판 / 그만뒀다 | |

- ③·④는 2단계의 자연어 입력과 "자기 말로 설명" 비교에 쓴다. ⑤~⑩은 앱이 추출해야 할 정답이다. ⑪·⑫는 전제 5의 근거다.
- 기록지는 친구 동의 없이 공유하지 않는다. 엔지니어링 쪽 평가셋(정답 평가, CEO-T4)에 쓸 때는 ③·⑤~⑩만 옮기고, 친구 번호로만 구분한다.

## 2단계 — 앱으로 테스트 (앱이 생긴 뒤)

### 준비물

- 친구별 초대 링크(`?t=토큰`, C3-1). 토큰은 친구 번호와 짝지어 적어 둔다.
- 서버 기록 파일 `data/logs/reviews.jsonl`이 켜져 있는지 확인한다(C8-1).
- 1단계 기록지.

### 친구에게 보여 줄 기록 동의 안내

> 테스트 중 입력한 문장과 복기 결과가 내 노트북에 기록돼. 기록되는 것은 다음과 같아.
> 입력한 문장, 앱이 이해한 내용과 네가 고친 부분, 원인 결과, 응답 시간, 마지막 질문("진짜 패인이었나요?")에 대한 답.
> 이름이나 계정은 기록하지 않고, 초대 링크 번호로만 구분해. 다른 사람에게 보내지 않아.
> 테스트가 끝난 뒤에도 지워 달라고 하면 바로 지울게.
> 동의하면 링크를 열어 줘.

동의를 받은 친구만 링크를 보낸다. 지워 달라는 요청이 오면 그 토큰의 줄을 `reviews.jsonl`에서 지우고, 지운 사실을 친구에게 알린다.

### 진행 (친구 1명당 약 15분)

1. **설명 없이 링크만 준다.** "그때 그 한 턴을 넣어 봐"라고만 말한다. 화면 사용법은 알려 주지 않는다.
2. **지켜보기만 한다.** 다음을 적는다.
   - 첫 입력까지 걸린 시간
   - 「더 정확하게」를 열었는지
   - 확인 단계에서 고친 칩
   - 막힌 곳과 그때 한 말
3. 결과가 나오면 30초 동안 읽게 둔다. 그 뒤 화면을 닫게 하고 아래 질문을 한다.

### 테스트 뒤 질문 (화면을 닫은 상태에서)

| # | 질문 | 적는 방식 |
|---|---|---|
| A | 방금 본 결과로는, 그 타격이 왜 그렇게 됐어? | **원래 말 그대로.** 원인 후보를 자기 말로 설명했는지 판정 |
| B | 다음에 같은 상황이면 뭘 다르게 할 거야? | 원래 말 그대로. 다음 행동을 자기 말로 설명했는지 판정 |
| C | 도움이 됐어? | 도움 됐다 / 그저 그렇다 / 아니다 + 이유 한마디 |
| D | 이상하거나 틀린 것 같은 게 있었어? | 원래 말 그대로 |
| E | 이런 게 있으면 다음 패배 때도 쓸 것 같아? | 쓸 것 같다 / 모르겠다 / 안 쓸 것 같다 |

앱 마지막의 "이 턴이 실제로 진 이유였나요?" 답은 기록 파일에서 읽는다. 1단계 ⑪과 다르면 둘 다 적는다.

## 3단계 — 판정 (C-O6)

### 친구별 판정표

| 친구 | A 원인을 자기 말로 설명 | B 다음 행동을 자기 말로 설명 | C 도움 됐다 | "진짜 패인?" 아니요 | 결과가 보류·확인 불가 | 확인 단계에서 고친 칩 수 | E 다시 쓸 것 같다 |
|---|---|---|---|---|---|---|---|
| 1 | O/X | O/X | O/X | O/X | O/X | n | O/X |
| 2 | | | | | | | |
| 3 | | | | | | | |

"자기 말로 설명했다"의 기준: 앱 화면의 문장을 그대로 외운 것이 아니라, 원인(예: "상대가 머리띠라서 세게 맞았다")이나 행동(예: "다음엔 반감 포켓몬으로 바꾼다")을 자기 표현으로 말했으면 O.

### 판정 규칙 (테스트 **전에** 확정하고 바꾸지 않는다)

- **계속:** 3명 중 2명 이상이 A **와** C(도움 됐다)에 O.
  - 미룬 기능(TODOS.md)은 기록 파일의 `unsupported` 빈도 순서대로 연다.
- **방향 수정:** A는 했지만 "진짜 패인?"에 "아니요"가 2명 이상.
  - 한 타격 설명은 통하지만 패인 찾기는 못 한다는 뜻이다.
  - 쐐기(한 턴 복기)를 다시 본다. 예: 여러 턴 입력, 팀 프리뷰 경보(설계의 접근 C).
- **중단:** 보류·확인 불가가 2명 이상이거나, 아무도 A를 하지 못함.
  - 미룬 기능을 열지 않는다. 전제 5와 계산 범위부터 다시 본다.
- 셋 다 아니면(예: 1명만 O): **방향 수정**으로 보고 친구를 2명 더 구해 반복한다.

숫자 기준은 사용자가 테스트 전에 조정할 수 있다. 조정했다면 아래 기록란에 적는다.

### 함께 볼 숫자 (판정에는 쓰지 않고 참고만)

- 자연어 추출: 친구 3건 중 확인 단계에서 고친 칩 수(C1-1 실사용 정확도)
- 규칙 질문으로 잘못 분류된 수(DR21)
- 응답 시간(첫 진행 표시까지, 결과까지)
- 정답 평가(CEO-T4)의 상위 3 적중률. %를 다시 보여 줄지(C-O1) 정할 때 쓴다.
