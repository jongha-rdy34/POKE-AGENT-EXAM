# 인계장: 세부 디자인 구현 시 참고 (사용자 지시, 2026-10-22)

작성: /plan-design-review 세션. **아직 설계·프로토타입에 반영하지 않았다.** 세부 디자인을 구현할 때(4단계 `web/`) 이 문서를 먼저 읽는다.

## 먼저 읽을 것

1. `agent.md` 1.2·1.3·8절
2. `docs/designs/loss-review-coach.md`: 승인된 설계와 엔지니어링 결정

4. 이 문서: 아래 지시가 DR4·DR5·DR10의 일부를 바꾼다. 충돌하면 이 문서가 우선한다. 단 사용자가 다시 정한 경우는 예외다.
5. 참고용 프로토타입: `docs/designs/prototype/review-tab.html` (지시 반영 전 버전)

## 지시 1. 자연어 질의를 먼저 받는다

**사용자 원문 요지**
- 사용자의 자연어 질의를 우선해서 받는다.
- 지금처럼 세부 내용을 요구하는 부분(포켓몬·기술·결과·빌드 등)은 선택 사항으로 남긴다.
- 그 위에 "아래의 사항을 기록해주시면 더 정확한 답변이 가능합니다"와 같은 문구를 둔다.

**DR4·DR5와의 관계**
- DR4는 "필수 = 대결 줄 4칸"이었다. 이제 **필수 = 자연어 입력 한 칸**이고, 대결 줄·결과 선택지·「더 정확하게」는 모두 선택 영역이 된다.
- DR5의 결과 선택지 문구는 선택 영역 안에서 그대로 쓸 수 있다.
- 결과 화면 순서(DR3), 상태표(DR7), 원인 표기(DR8), 가정 줄(DR9)은 그대로 유효하다. 특히 DR9의 "계산 가정" 줄은 자연어만 입력한 경우에 더 중요해진다.

**구현 전에 정해야 할 것(미결)**
- **파싱 주체:** 자연어("망나뇽 역린에 한카리아스가 한 방에 죽었어")에서 `my_form_key`·`opp_form_key`·`actor`·`move_key`·`actual`을 누가 뽑는가.
  - agent.md 1.2에 따라 화면 JS는 파싱하지 않는다. 서버에서 별칭 사전·정규식으로 할지, 프롬프트 1(구조 추출)로 할지는 엔지니어링 결정이다.
  - 설계 원칙 "LLM은 판정하지 않는다"와의 관계도 정해야 한다. 추출과 판정은 다르지만 확인이 필요하다.
- **API 계약:**
  - `POST /api/feature/review`에서 `text`가 주 입력이 되고 구조화 필드는 선택이 된다(R8의 `text?`는 지금 SP 표기용이다).
  - 둘 다 오면 구조화 값이 우선인지 정해야 한다.
- **추출이 불완전할 때의 화면:**
  - 예: 포켓몬은 찾았지만 결과를 못 찾은 경우. 이때 계산을 막을지, 찾은 값을 선택 영역에 미리 채워 보여 주고 "이렇게 이해했어요, 맞나요?"를 확인받을지 정해야 한다.
  - 상태표(DR7)에 "이해한 내용 확인" 상태가 추가될 가능성이 크다.
- **채팅과의 경계:** 자연어 입력창이 복기 탭의 입력이면서 동시에 채팅 입력과 같아 보인다. 복기 요청과 일반 질문(`POST /api/chat`)을 어떻게 구분할지 정해야 한다(입력창 하나로 의도를 분류할지, 탭으로 나눌지).
- **안내 문구:** "아래의 사항을 기록해주시면 더 정확한 답변이 가능합니다"는 자연어 입력창 바로 아래, 선택 영역 바로 위에 둔다. 선택 영역은 기본으로 펼칠지 접을지 정해야 한다. 뉴비 기준으로는 접힘을 권장하지만 확인이 필요하다.

## 지시 2. 첫 화면 배틀 애니메이션 영상과 채팅 칸 배경

**사용자 원문 요지**
- 영상은 아직 준비되지 않았다.
- 첫 페이지 진입 시 짧은 포켓몬 배틀 애니메이션 영상이 재생된다.
- 자연어 질의가 들어갈 채팅 칸을 감싸는 이미지/동영상을 깔아 두는 디자인을 계획한다.

**DR10과의 관계**
- DR10은 "카드·그림자·아이콘·장식 없음, 시각 앵커 = 대결 줄"이었다.
- 첫 화면은 이제 영상과 채팅 칸이 앵커가 되고, 마케팅에 가까운 첫 화면(HYBRID)이 된다. 복기 결과 영역은 DR10 규칙을 유지하는 것을 권장한다. 첫 화면만 연출하고, 작업 화면은 조용하게 둔다.

**구현할 때 지켜야 할 것(디자인 원칙과 명세에서 나온 것)**
- **글자 가독성:** 배경 이미지·영상 위의 입력창·안내 문구는 대비 4.5:1 이상을 유지한다. 영상 위에 단색 막(scrim)을 깔거나, 입력창 자체에 불투명 배경을 둔다. "글자 뒤의 복잡한 이미지"는 디자인 금지 패턴이다.
- **재생 정책:**
  - 자동 재생은 `muted` + `playsinline`일 때만 브라우저가 허용한다.
  - 「건너뛰기」 버튼을 두고, 재방문 때는 다시 재생하지 않는 것을 권장한다.
  - `prefers-reduced-motion: reduce`이면 정지 이미지(포스터)만 보여 준다.
- **입력 지연 금지:** 영상이 끝날 때까지 입력창을 막지 않는다. 뉴비는 패배 직후 바로 묻고 싶어 한다(여정 1단계). 영상 재생 중에도 입력할 수 있어야 한다.
- **모바일 데이터와 성능:**
  - 파일은 짧고 작게 만든다(예: 수 초, 수 MB 이하). 포스터 이미지를 먼저 보여 준다.
  - `preload="metadata"`를 쓰고, 영상 위에 첫 화면을 그리지 않는다(LCP).
- **접근성:** 소리 없는 장식 영상이면 `aria-hidden`을 두고, 의미가 있으면 대체 텍스트를 단다. 키보드 포커스가 영상에 갇히지 않게 한다.
- **IP 위험(전제 4·Constraints):**
  - 포켓몬 배틀 애니메이션은 게임 화면·공식 아트를 쓰면 닌텐도·포켓몬 IP 문제가 생길 수 있다.
  - 직접 제작한 애니메이션인지, 게임 캡처인지에 따라 위험이 다르다.
  - 영상 출처와 이용 조건을 agent.md 2절(데이터 출처와 이용 조건) 수준으로 기록한다.
- **파일 위치:** agent.md 1.2에 따라 `web/` 정적 파일로 둔다(예: `web/media/intro.mp4`, `web/media/intro-poster.jpg`). 외부 프레임워크·빌드 도구는 쓰지 않는다.

**구현 전에 정해야 할 것(미결)**
- 영상 출처(직접 제작 / 외부 의뢰 / 게임 캡처)와 IP 처리
- 영상이 끝난 뒤 첫 화면 구성: 영상을 정지 프레임으로 남겨 배경으로 쓸지, 별도 배경 이미지로 바꿀지
- 첫 화면이 복기 탭과 같은 화면인지, 별도 랜딩인지(탭 구조 D12와의 관계)
- 영상 준비 전 임시 처리(정지 이미지 또는 단색)

## 후속

- 위 미결 사항은 엔지니어링 결정(파싱 주체·API 계약)과 디자인 결정(첫 화면 구성·영상 처리)으로 나뉜다. 엔지니어링 재리뷰와 디자인 재리뷰(`/plan-design-review` 재실행) 때 다룬다.
- 프로토타입 `review-tab.html`은 이 지시를 반영하지 않은 상태다. 세부 디자인 때 자연어 우선 구조로 다시 만든다.

## 엔지니어링 세션 추가 사항 (2026-10-23, 디자인 초안 확인 결과)

디자인 재리뷰(DR20~DR22)와 프로토타입은 CEO 결정(C0 자연어 우선, C-O1 % 숨김)과 "출처 꼬리표 두 개"를 반영했다. **아래 한 가지는 아직 빠져 있다.**

- **통계 이중 기준 표시 (설계 v1.3, D31·D32, 2026-10-22 사용자 지시):** 코드가 pokedb M-6 기준과 Smogon(지난달, Pokémon Showdown) 기준으로 복기를 **각각** 계산한다. 지금 프로토타입은 "도구 = pokedb, 성격·SP·특성 = Smogon"으로 나눠 한 결과만 보여 준다. 필요한 화면:
  - 두 기준의 차이가 유의미할 때(원인 1순위 도구가 다르거나 같은 원인의 확률 차이 ≥ 20%p, 통계 답변은 1위가 다르거나 채용률 차이 ≥ 10%p) **두 결과를 나란히** 보여 준다. 예: "실제 게임 상위 구축(pokedb M-6) 기준 1순위: 구애머리띠 / Showdown 래더(Smogon 2026-09) 기준 1순위: 생명의구슬".
  - Smogon 쪽에는 반드시 **"Pokémon Showdown(시뮬레이터) 환경에서 수집된 데이터"**를 붙인다.
  - 차이가 없으면 한 결과로 합치고 근거에 두 출처를 모두 인용한다.
  - C-O1(% 숨김)과 함께 쓰므로 비교도 순위·"16번 중 k번"으로 표시한다(내부 확률 차이는 판정에만 쓴다).
  - 두 출처의 "채용률"은 모집단이 다르다(pokedb = 상위 구축 팀, Smogon = 래더 전체 가중). 비교 문구에 모집단을 함께 밝힌다.
