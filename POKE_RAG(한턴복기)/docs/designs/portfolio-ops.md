## Problem Statement

복기 서버(`server/`)와 화면(`web/`)은 동작한다. 그러나 이 PC 안에서만 돌고, 사용자는 0명이다. 2026-10-22 설계의 전제 4(수익은 광고뿐, 나중에 판단)를 접는다. 대신 이 프로젝트를 **서비스 기획/풀스택 포트폴리오**로 만든다. 포트폴리오가 증명할 것은 두 가지다. 실제 사용자가 쓰는 서비스를 배포해 운영해 본 경험이 하나, 사용자 기록을 보고 서비스를 고친 경험이 다른 하나다.

## What Makes This Cool

면접관에게 대시보드를 보여 주는 것은 흔하다. 이 프로젝트가 보여 줄 것은 **실제 사용자의 불만 한 줄이 수정과 고정 테스트로 이어진 고리**다. 첫 항목은 이미 있다.

- 친구가 물었다. "빠르모트가 그렇게 빠르지 않는데 왜 내 CS 조심 메한카Z가 죽은거지"
- v1.3은 "통계상 이유 없음"이라고 답했다.
- 원인은 두 가지였다. 철주먹을 계산하지 않았고, 통계에 없는 도구(구애머리띠)는 후보에서 빠졌다.
- v1.4에서 스마트누오와 같은 결과(6.3%와 75.0%)가 나오게 고쳤고, `tests/test_calculator.py`와 `tests/test_server.py`에 고정했다.

이런 고리를 공개 개선 일지(`/changelog`)로 쌓는다. 각 항목에 사례, 원인, 수정, 테스트, 지표 변화를 적는다.

## Constraints

- 비상업이다. 광고와 결제는 없다. 화면에 "비공식 팬 도구"라고 표기한다(포켓몬 IP, 기존 전제 4를 대체).
- 기존 결정(D·R·C·C-O 번호)은 다시 논의하지 않는다. 데이터 우선순위(agent.md 1.3), pokedb 오픈데이터만 사용, Bulbapedia 5초 간격, M-6/Smogon 시즌 기준을 그대로 둔다.
- 개인정보 범위는 CEO C8-1을 따른다. 기록에는 이름표만 남기고, 키·프롬프트·토큰 비밀값은 남기지 않는다.
- LLM 키: SSAFY GMS 키가 2026-10-23에 만료된다. 이후에는 사용자의 유료 OpenAI API 키를 쓴다. 비용 상한은 이미 있는 서버 전체 하루 LLM 호출 한도(`server/access.py` `Quota`)로 건다.
- 작업 장소: 2026-10-24부터 개인 노트북에서 작업한다(`docs/HANDOFF-machine-migration.md`).
- SSAFY 네트워크는 cloudflared(7844 TCP/UDP), localhost.run(22), serveo(22)를 막는다. Pinggy(ssh 443)만 열린다. DNS도 터널 주소를 풀지 못한다(2026-10-23 확인).
- 커밋은 사용자가 직접 한다.

## Premises

1. 포트폴리오의 증거는 "실사용자 사례 → 원인 → 수정 → 고정 테스트" 고리다. 대시보드는 그 고리를 보여 주는 수단일 뿐이다. (동의)
2. 사용자 추적은 기존 `data/logs/reviews.jsonl` 이벤트를 넓혀서 한다. GA 같은 외부 분석 도구는 넣지 않는다. (동의)
3. 순서 (사용자가 수정): ① 오늘 친구 3명 테스트(Pinggy 터널) → ② 백업과 키 교체 → ③ 노트북에서 클라우드 배포 → ④ C-O6 판정이 '계속'이면 커뮤니티 경로별 토큰을 연다.
4. 비상업을 유지한다. 수익화 질문은 닫는다. (동의)
5. learnset이 빈 14개 폼, E3 다음 행동 규칙, "통계로 보면" 구역 정리는 기존 규칙대로 친구 테스트 결과를 보고 순서를 정한다. (동의)

## Approaches Considered

- **A) 로그 퍼널만, 노트북 터널:** 기각. 터널은 배포 경험이 아니다. 오늘 확인했듯이 노트북 터널은 네트워크에 따라 막힌다.
- **C) B + 공유 결과 페이지(`/r/<id>`) + 커뮤니티 답글:** 미룸. C-O6 '계속' 판정 뒤에 착수한다. 공개 페이지에서 입력 문장을 어떻게 다룰지(C8-1)도 그때 정한다.

## Recommended Approach

**B) 클라우드 배포 + 퍼널 기록 + 개선 일지**

### B1. 배포

- **이미지:** `Dockerfile` 하나로 만든다. Python 3.12, `requirements.txt` 설치, 실행 명령은 `uvicorn server.app:app --host 0.0.0.0 --port 8000 --no-access-log`이다.
- **데이터는 이미지에 넣지 않는다.** `data/processed/pokedex.sqlite`, `chroma_db/`(48MB), `data/raw/`, `data/logs/`는 VM 영구 디스크에 마운트한다. 이미지가 바뀌어도 기록과 색인이 남는다.
- **호스트:** 영구 디스크가 있는 작은 VM 한 대를 쓴다. 무료 PaaS 중 영구 디스크가 없는 곳은 제외한다(로그와 SQLite가 재시작 때 사라진다). 어느 업체를 쓸지는 Open Question 1이다.
- **HTTPS·주소:** 도메인 하나와 리버스 프록시(Caddy 자동 인증서)를 쓴다. 도메인을 사지 않는다면 VM에서 cloudflared 고정 터널을 쓴다(클라우드 VM은 SSAFY 망 제한을 받지 않는다).
- **CI/CD:** 비공개 GitHub 저장소에서 GitHub Actions를 돌린다. 푸시하면 `python -m unittest discover -s tests -t .`를 실행하고, 통과하면 이미지를 빌드해 VM에 배포한다. 비밀값(`OPENAI_API_KEY`, `INVITE_TOKENS`)은 VM의 `.env`에만 두고 저장소에는 넣지 않는다.
- **비용 상한:** 서버 전체 하루 LLM 호출 한도를 그대로 쓴다. 일일 사용량은 기록에서 집계한다.

### B2. 사용자 추적 (퍼널)

- **이벤트:** 기존 `extract`, `review`, `feedback`에 `visit`(화면 첫 로드, 이름표·시각만)를 더한다. C를 열 때 `share`를 더한다.
- **퍼널:** 방문 → 문장 입력(extract) → 복기(review) → "도움 됐어요"(feedback) → 7일 안에 다시 복기. 이름표별로 본다.
- **유입 경로:** 초대 토큰을 사람마다가 아니라 경로마다 하나씩 만든다(`friend1`, `arca`, `dc` 등). 이름표가 곧 유입 경로 표시가 되므로 `server/access.py`를 고칠 필요가 없다.
- **집계:** `data/eval/aggregate_reviews.py`를 넓혀 퍼널 표를 출력한다. 화면 대시보드는 만들지 않는다. 집계 결과는 개선 일지 항목의 "지표 변화" 칸에 들어간다.

### B3. 개선 일지 (`/changelog`)

- 저장소의 `docs/changelog.md` 한 파일을 정적 페이지로 보여 준다.
- 한 항목에 들어가는 칸: 날짜, 사례(익명 이름표), 사용자가 한 말, 원인, 수정 내용(파일), 고정 테스트, 지표 변화.
- 첫 항목은 친구 사례 1(v1.4)이다. 오늘 친구 테스트에서 나온 사례가 다음 항목이 된다.

## Open Questions

1. VM 업체와 월 비용 한도. 무료 VM(예: 무료 등급이 있는 클라우드)이나 월 몇 천 원대 VPS 중 무엇을 쓸지. 사용자가 비용 상한을 정한다.
2. 도메인을 살지, cloudflared 고정 터널 주소로 갈지.
3. `visit` 이벤트에 무엇까지 남길지. 이름표와 시각만 남길 것을 제안한다. User-Agent는 남기지 않는다(C8-1).
4. 친구 테스트(C-O6) 판정 숫자는 그대로 둘지. 3명 중 2명이 원인을 자기 말로 설명하고 "도움 됐다"고 하면 '계속'으로 본다.
5. 오늘 쓴 Pinggy 링크는 60분 뒤 끊긴다. 친구가 나중에 열면 새 링크가 필요하다.

## Success Criteria

- 친구 3명 테스트가 끝나고 C-O6 판정(계속·수정·중단)이 기록된다.
- 저장소에 첫 커밋이 있고, 비공개 원격 저장소와 `.gitignore` 밖 데이터 압축본이 있다.
- 노트북을 꺼도 서비스가 HTTPS 주소에서 동작한다. 푸시하면 테스트를 거쳐 자동으로 배포된다.
- `aggregate_reviews.py`가 이름표별 퍼널 표를 출력한다.
- `/changelog`에 항목이 2개 이상 있고, 각 항목이 테스트 파일을 가리킨다.

## Distribution Plan

웹 서비스다. 위 B1의 Docker 이미지와 GitHub Actions로 VM에 배포한다. 사용자는 경로별 초대 링크로 들어온다.

## Next Steps

1. **오늘:** 친구 3명에게 Pinggy 링크를 보내 테스트한다(`docs/friend-test-kit.md`). 결과는 `reviews.jsonl`에 이름표별로 쌓인다.
2. **오늘 (PC 반납 전):** 첫 커밋을 만들고 비공개 GitHub 원격 저장소에 푸시한다. `.gitignore`에 있는 `data/raw/pokedb/`, `chroma_db/`, `data/logs/`, `.env`는 별도 압축본으로 옮긴다(`.env`는 메신저로 보내지 않는다).
3. **노트북:** 새 OpenAI API 키를 받는다. `.env`의 `OPENAI_BASE_URL`을 비우고 임베딩 호환을 확인한다(HANDOFF-machine-migration 1~3).
4. `visit` 이벤트를 추가하고 `aggregate_reviews.py`에 퍼널을 넣는다.
5. Dockerfile을 쓰고 VM을 준비한다. 영구 디스크에 데이터를 둔다.
6. GitHub Actions(테스트 → 빌드 → 배포)와 HTTPS를 설정한다.
7. `docs/changelog.md`와 `/changelog` 경로를 만들고, 친구 사례 1과 오늘의 사례를 적는다.
8. C-O6 판정이 '계속'이면 C(공유 페이지와 경로별 토큰)를 설계한다(/plan-eng-review).

## What I noticed about how you think

- 수익화를 스스로 접었다. "무리한 수익화보다는 추후 포트폴리오를 위한 배포경험/사용자 추적을 통한 서비스 develop" 이 판단은 포켓몬 IP 위험과 맞아떨어진다.
- 계획을 끝까지 다듬기 전에 실행을 앞당겼다. "친구 테스트를 지금 진행합니다. 친구가 접근할 링크를 첨부하면 내가 바로 전달하겠습니다." 배포 계획보다 실제 사용자를 먼저 택했다.
- 운영 문제를 같은 무게로 챙겼다. "저장소 백업/GMS key 갱신과 같은 문제도 todo list에 올려야합니다." 커밋 0개와 오늘 만료되는 키는 지금 가장 큰 위험이다.
- 첫 30명이 어디서 올지는 아직 "아직 모름"이다. C를 미룬 이유이자, 친구 테스트 다음에 답해야 할 질문이다.
