# 인계장: 디자인 → 엔지니어링 (web/ 적용 전 합의, 2026-10-23)

받는 사람: 엔지니어링 에이전트. 보낸 쪽: 디자인 세션.
목적: 수정된 디자인을 `web/`에 옮기기 **전에** 서버 응답과 화면이 맞는지 합의한다. 사용자는 엔지니어링 답변을 본 뒤 적용 여부를 정한다. **답변 전에는 `web/`에 옮기지 않는다.**

## 디자인 쪽 남은 일 (합의와 별개)

- "통계로 보면" 구역이 계산표와 일부 겹친다. 줄이거나 접을지는 사용자 결정 대기.
- 포켓몬·도구 이미지: 저작권 확인 전까지 쓰지 않는다(DESIGN.md: 공식 아트 금지).
- 옮긴 뒤 `web/`을 `/design-review`로 시각 검수한다.

## 확인하지 않은 것

- `web/` 실제 화면은 열지 않았다(시안만 검수). 사용자가 보낸 web/ 스크린샷 1장으로 문제를 확인했을 뿐이다.
- 스크린 리더 실제 낭독.
- 실제 서버 SSE를 시안에 붙여 보지 않았다(샘플 JSON만 사용).

## 엔지니어링 답변

2026-10-23, 엔지니어링 세션. 근거는 현재 코드(`server/app.py`·`server/extract.py`·`server/summary.py`·`prep/review.py`)를 읽고 확인한 것이다. 서버 쪽 작업(E1·E2)은 사용자가 적용을 정하면 바로 할 수 있다(CC 약 30분, `web/`과 무관). 끝나면 `samples/*.json`을 다시 만들어 시안에 넘긴다.

| # | 답 | 내용 |
|---|---|---|
| E1 | **동의** | `headline` 필드를 추가한다. LLM이 아니라 **코드가 계산표에서 한 문장을 만든다**(숫자는 `k`만, 괄호 속 난수·% 없음). 규칙은 아래 "E1 문장 규칙"에 적었다. 계산을 하지 않는 기술처럼 `calc`가 없으면 `headline`은 `summary` 첫 문장이다. `summary`는 지금처럼 보내되, 화면에서는 h1 아래 문단으로 쓴다. |
| E2 | **동의(일부 수정)** | `bases.*.notes`의 내 빌드 가정은 계산표의 `my_build`와 같은 꼴("고집 · H32 B32 · 특성 모래숨기 · 구애스카프")로 바꾼다. `unsupported`의 기술 이름도 한글로 바꾼다. 특성은 이미 한글이다("계산하지 않은 상대 특성: 축전"). SSE `bad_input` message도 한글 이름으로 바꾼다. 다만 **화면은 디자인 문구표의 고정 문구를 쓰는 것에 동의**한다. message는 기록·디버그용으로 남긴다. `diff_reason`은 화면에 내지 않는다는 결정에 동의하므로 고치지 않는다(기록용). |
| E3 | **불가(지금은)** | "다음 대전에서"는 조언 규칙(예: 이 타입을 반감하는 포켓몬으로 받기)을 정해야 한다. 그런데 사용자의 파티를 모르고, 틀린 조언은 계산보다 위험하다. 설계 결정(C-O3 조건부 문구)도 아직 정해지지 않았다. 친구 테스트 1차 결과를 보고 사용자가 규칙을 정한 뒤에 넣자고 제안한다. 그때까지는 디자인 제안대로 화면에서 뺀다. |
| E4 | **동의** | `near`는 `rows`와 같은 함수(`summary.public_calc`의 `row`)로 만든다. 그래서 필드가 같다: `label, in_champions, same_items, usage, k, pct, damage`. 차이 세 가지: ① `near`는 `rows`가 비었을 때만, 최대 2줄이다. ② 데미지 결과(`ko`·`survived`)에서만 오고, 스피드 결과에서는 항상 빈 배열이다. ③ `k`가 0일 수 있다(→ "1타 불가"). |
| E5 | **수정(보충)** | 목록에 다음을 더해 주세요. ① **422는 `code`가 없다.** FastAPI 기본 형식 `{"detail": [ {loc, msg, type}… ]}`라서 HTTP 상태로 고른다. ② **429는 문장 읽기와 복기 둘 다에서 온다.** 토큰당 한도가 따로 있다(복기 50·문장 읽기 100/일, `code`는 둘 다 `token_limit`). `server_limit`은 서버 전체 LLM 호출 400/일이다. 문장 읽기의 `token_limit`에 "복기 횟수를 다 썼어요"는 정확하지 않다. "오늘 이용 횟수를 다 썼어요"를 권한다. ③ **403 `no_token`은 모든 `/api/*`에서 온다**(검색·기술 목록·남은 횟수 포함). ④ 피드백 응답 `{"ok": false}`: 기록 쓰기 실패다. 화면에는 "기록하지 못했어요" 정도면 된다. ⑤ **잘못된 초대 링크(`?t=틀린값`)로 첫 화면을 열면 지금은 JSON 403이 그대로 보인다.** 서버를 고쳐 `t`를 뗀 주소로 보내고(303), 화면이 403 초대 안내(상태 16)를 띄우게 하겠다. 서버만 고치면 된다. 표에 없는 code는 서버 message를 그대로 쓴다는 원칙에 동의한다. |
| E6 | **동의(보충)** | 연결은 맞다. 다만 지금 서버가 `ask`에 넣는 칸은 **`actor`·`move_key`·`actual` 셋뿐**이다. `my_form_key`·`opp_form_key`는 `ask`에 오지 않고, 못 찾으면 `missing`으로 온다. `actor`가 오는 경우: 같은 포켓몬끼리(미러), learnset으로 공격 측을 바꾼 경우, 스피드 결과에서 공격 측을 코드가 채운 경우. 셋 다 "누가 공격했나"가 불확실하다는 뜻이라, 공격한 포켓몬 칩 + 교체 버튼(⇄)을 강조하면 맞다. |
| E7 | **동의** | `remaining`은 `GET /api/quota`에만 실린다: `{"remaining": {"review": n, "extract": m}}`. `web/`은 화면을 열 때와 복기가 끝날 때마다 다시 부른다. 표시는 `review`만으로 충분하다. 다른 응답에 넣지는 않는다(호출 한 번이 가볍다). |
| E8 | **수정** | 좌우 배열은 **JS가 `differs`일 때 `.bases.two`를 붙이는 방식**을 권한다. 화면은 이미 `differs`를 알고 있고, 친구들 기기(삼성 인터넷·카카오톡 내부 브라우저 등)의 `:has()` 지원을 확인하지 못했다. 배치가 깨지면 결과 표가 깨진다. `:has()`는 지금처럼 꾸밈 용도(확인 단계의 버튼 강조)에만 쓴다. CSS 선택자는 `@media (min-width: 1200px) { .bases.two { … } }`로 바꾸면 된다. |

### E1 문장 규칙 (서버가 만드는 `headline`)

계산표의 첫 줄(챔피언스 도구 우선 정렬)을 기준으로 한다. 이름은 `label` 대신 짧은 꼴(성격 + 도구, 특성이 결과를 가르면 특성 포함)을 쓴다.

| 상황 | 문장 |
|---|---|
| 한 방, 첫 줄이 챔피언스 도구, 챔피언스에 없는 도구 줄의 k가 더 큼 | 챔피언스에 있는 도구로는 16번 중 {k}번만 한 방이에요 |
| 한 방, 첫 줄이 챔피언스 도구 | 상대가 {성격} {도구}면 16번 중 {k}번 한 방이에요 (k=16이면 "확정 1타예요") |
| 한 방·버팀, 결과가 나오는 줄이 챔피언스에 없는 도구뿐 | 지금 챔피언스에 있는 도구로는 이 결과가 나오기 어려워요 |
| 버팀 | 상대가 {성격} {도구}면 16번 중 {k}번 이 HP로 버텨요 |
| 상대가 먼저(스피드), 도구 없음 줄이 성립(첫 줄이 아니어도 우선) | 상대 {포켓몬}{은/는} 도구 없이도 내 {포켓몬}보다 빨라요 |
| 상대가 먼저, 도구가 있어야 성립 (디자인 보충: 구애스카프 → 도구 일반화) | 상대 {포켓몬}{이/가} {도구}{이면/면} 내 {포켓몬}보다 빨라요 |
| 내가 먼저(slower) (디자인 보충) | 상대가 {성격} {도구}{이면/면} 내 {포켓몬}보다 느려요 (도구 없음 줄이 성립하면 "상대가 도구 없이 {성격}이면") |
| 결과가 나오는 줄 없음(`near`만) | 상대가 흔한 빌드라면 계산상 이 결과가 나오기 어려워요 |
| `calc` 없음(계산 안 하는 기술 등) | `summary` 첫 문장 |

- 참고용(`reference_only`)이어도 문장은 같다. "참고용" 배지는 화면이 붙인다.
- 문장 규칙을 바꾸고 싶으면 이 표를 고쳐 주세요. 서버는 이 표를 그대로 구현한다.

### 디자인 쪽에 알릴 것 (답변과 별개)

- `pct`는 반올림이다(1/16 = 6.3, 계산기 관례). 끝의 .0을 빼는 것은 화면에서 한다.
- 계산표 `rows`에는 결과가 나오는 줄(`k` > 0)만 온다. 그래서 `rows` 안에서 `k`=0인 "1타 불가"는 `near`에서만 나온다.
- 버팀 결과의 `k`는 "그 HP 구간으로 버틴 난수 수"다. 데미지가 약한 빌드일수록 크다(한 방과 반대 방향).
- 서버 쪽 작업(E1·E2·E5⑤)을 마치면 `samples/*.json`을 다시 만들고 이 절 아래에 적는다. 시안의 손으로 넣은 `headline`은 그때 서버 값으로 바꿔 주세요.

### 서버 작업 완료 (2026-10-23, 진행 순서 1번)

- **E1 `headline`**: 위 문장 규칙 표대로 구현했다(`server/summary.py` `headline`, 디자인 보충 2줄 포함).
  - 표에 한 가지를 더했다: 스피드 결과에서 "도구 없음" 줄이 성립하면 첫 줄이 아니어도 그 줄로 쓴다("도구 없이도 빨라요"가 더 강한 답이라서).
  - 받침에 따라 이면/면, 은/는, 이/가를 고른다.
- **E2 한글화**:
  - `bases.*.notes`의 내 빌드 가정이 "H32 B32 · 장난꾸러기 · 구애스카프 · 특성 모래숨기" 꼴이 됐다.
  - `unsupported`의 기술 이름이 한글로 나온다("…: 바디프레스").
  - SSE `bad_input` message는 알 수 없는 키를 그대로 담는다(사용자가 보낸 잘못된 값이라 한글 이름이 없다). 화면은 고정 문구를 쓰므로 영향 없다.
- **E5 ⑤ 잘못된 초대 링크**:
  - 화면 주소 `/?t=틀린값`은 303으로 `t`를 뗀 주소로 보낸다. 쿠키는 지운다. 그다음 API 403을 받아 초대 안내가 뜬다.
  - `/api/*`는 그대로 403 JSON이다. 실서버에서 확인했다.
- **응답 예시**: `samples/*.json`을 새로 만들었다. 모든 review 예시에 `headline`이 있고, `review-slower.json`을 새로 넣었다.
  - 다시 만들 때는 `.venv/Scripts/python -m docs.designs.samples.make_samples`(서버와 같은 `summary.answer`를 쓴다)를 실행한다.

## web/ 이식 완료 (2026-10-23, 진행 순서 4번, 엔지니어링)

- **옮긴 것:**
  - `web/index.html`: 시안의 마크업·CSS를 그대로 썼다. 시안 전용 안내·상태 전환 패널은 뺐다. 성격·도구 선택은 서버 키 값으로 바꿨다.
  - `web/app.js`: 시안의 화면 코드(문구표 `MSG`, 확인 칩, `#confirmSwap`, 계산표, 두 기준 `.bases.two`, 피드백 `#fbStatus`)를 그대로 옮겼고, 예시 데이터 자리만 실제 API로 바꿨다.
- **시안과 값이 다른 곳(서버에 맞춤):** 화면은 시안 그대로이고, 서버로 보내고 받을 때만 바꾼다.

  | 무엇 | 시안 | 서버 |
  |---|---|---|
  | HP 칸 | `-25` | `<25` |
  | 피드백 "모르겠어요" | `unknown` | `unsure` |
  | `ask`의 기술 칸 | `move` | `move_key` |

  - 결과 종류(`kind`)는 응답에 없어서, 화면이 보낸 요청에서 붙인다.
- **시안과 다르게 한 곳 하나:** 확인 단계의 "공격 측 바꾸기 ⇄"(`#confirmSwap`)는 **기술 칸을 비우지 않는다.**
  - 시안은 「더 정확하게」의 ⇄를 그대로 눌러 기술까지 지웠다.
  - 서버가 `actor`를 확인 대상으로 보낼 때는 기술은 맞게 읽었고 "누가 썼는지"만 불확실한 경우라서 기술을 남겼다.
  - 「더 정확하게」 안의 ⇄는 시안대로 기술을 지운다.
- **시안에도 있는 버그(고쳐 주세요):** `review-tab.html` 477줄 `if (e.target.closest("[data-all]"))`.
  - 「전체 기술에서 찾기」를 누르면 묶음(`.combo`)에 `data-all="1"`이 붙는다. 그다음부터는 기술을 눌러도 이 조건에 걸려 목록만 다시 그리고 **고를 수 없다.**
  - `web/`은 `closest("button[data-all]")`로 고쳤다.
- **검사:**
  - `node --check` 통과.
  - jsdom에 `web/` 화면을 띄워 실서버(GMS)로 친구 사례를 끝까지 돌렸다: 초대 없음 → 초대 안내 / 문장 읽기 → 확인(성격 조심·H2 C32 S32 자동 채움, 기술 빈 칩) → 「전체 기술에서 찾기」로 냉동펀치 → 결론 h1 "챔피언스에 있는 도구로는 16번 중 1번만 한 방이에요" → 계산표 3줄과 "챔피언스에 없는 도구" 묶음 → 피드백 기록 → 기록 삭제.
  - **실제 브라우저 화면(배치·색·좌우 배열)은 보지 않았다.** `/design-review`로 검수해 주세요.
- **데이터 쪽에서 알게 된 것:** 챔피언스 폼 336개 중 14개는 배우는 기술(learnset)이 비어 있다. PokeAPI와 champions-data 모두 챔피언스 기술이 없다.
  - 해당 폼: 빠르모트, 갑주무사·메가갑주무사, 보만다·메가보만다, 에이스번, 고릴타, 드닐레이브·메가드닐레이브, 올리르바, 에써르 암·수, 스트린더 두 폼.
  - 이 포켓몬이 공격하면 기술 목록이 비고 「전체 기술에서 찾기」로만 고를 수 있다.
  - 서버의 공격 측 검증(learnset)도 이 폼에서는 일하지 않는다.
  - 보충 출처(예: Showdown `data/mods/champions/learnsets.ts`)는 사용자 결정 대기다.
