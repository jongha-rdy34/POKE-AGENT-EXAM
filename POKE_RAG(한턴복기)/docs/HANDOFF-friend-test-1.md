## 항목별

### F1 최악 빌드부터 내려가며 계산 (사용자 지시)
- **사용자 말:** "데미지의 가능성/스피드 추월의 가능성은 최댓값부터 시작해서 내려가며 계산해야합니다. 실제 계산기를 사용하면 복기할 때도 그렇게 합니다. 즉, 난수 확률로 죽을 가능성이 생길 때까지 최댓값에서 낮춰갑니다."
- **규칙:**
  - 상대는 가장 센 빌드부터 시작한다. 예: 메가리자몽Y면 C32 S32 조심. 거기서 성격, SP, 도구 순으로 낮춰 가다가 난수로 결과가 처음 나오는 지점에서 멈춘다.
  - 내 빌드가 없으면 가장 잘 죽는 빌드를 가정한다. 예: 마기라스는 내구에 투자하지 않은 A32 S32.
  - 내 특성으로 생기는 날씨(마기라스의 모래날림)는 반영한 경우와 반영하지 않은 경우를 둘 다 계산한다(F2).
  - 스피드도 같다. 상대 최고 스피드(S32 + 스피드 보정 성격, 예: 겁쟁이)부터 비교한다.
- **지금과의 차이:** `calc_table`은 SP 32 고정에 보정·무보정 성격을 돌리고, 결과가 나오는 줄만 보인다. 내 빌드가 없으면 pokedb 도구 1위 + 관련 스탯 SP 32 + 보정 성격을 가정한다(친구 사례 R5의 "내 빌드 가정"). F1은 이 내 빌드 가정을 "가장 불리한 쪽"으로 바꾼다.
- **결정이 필요한 것:** 통계 기반 "내 빌드 가정"(D25 계열)을 대체할지, 두 기준 다 보일지. 사용자에게 묻는다.
- **확인:** 피드백의 예(메가리자몽Y C32 조심 솔라빔 → A32 S32 마기라스, 모래 있음/없음)를 Showdown 계산기와 대조하는 테스트를 `tests/test_calculator.py` 친구 사례 옆에 추가한다.

### F9 성격 미입력 시 생명의구슬 줄이 사라짐 (재현됨)
- **재현(2026-10-23, 테스트 86개 통과 상태):**
  ```python
  from prep import calculator as c, review as rv
  db = c.connect()
  base = {"my_form_key": "garchomp-mega-z", "opp_form_key": "pawmot", "actor": "opp",
          "move_key": "ice-punch", "actual": {"kind": "ko"}, "flags": []}
  rv.review(db, {**base, "my_build": {"sp": {"spa": 32, "spe": 32, "hp": 2}, "nature": "careful"}})  # 생명의구슬 1/16, 구애머리띠 12/16·4/16
  rv.review(db, {**base, "my_build": {"sp": {"spa": 32, "spe": 32, "hp": 2}}})                       # 구애머리띠 4/16 한 줄뿐
  ```
- 성격을 비우면 화면의 내 빌드 줄에는 "장난꾸러기"라고 나온다. 그런데 장난꾸러기를 직접 넣으면 생명의구슬 줄이 나온다. **계산에 쓰는 가정 성격과 표시하는 성격이 다를 가능성이 높다.** `prep/review.py`에서 내 빌드 성격을 채우는 곳부터 본다.
- 친구 사례 1(v1.4) 테스트는 성격을 넣은 입력이라 이 경로를 잡지 못했다. 성격을 비운 입력도 테스트에 추가한다.

### F5 확정 2타
- "두 방에 죽었어"가 `actual.kind = ko`(한 방)로 추출됐고, 앱에는 두 방 결과 칸이 없다(R4). 친구가 "버텼어요 25~50%"로 바꾼 뒤에야 계산이 나왔다(R5).

### F3 메가진화 폼은 도구 고정
- 메가리자몽Y처럼 메가 폼이면 도구는 메가스톤으로 정해져 있다. 그래서 생명의구슬, 달인의띠 같은 도구 후보를 계산하면 안 된다(R3). 내 쪽이 메가일 때도 같다(현재 내 빌드 줄은 한카리아스나이트Z로 맞게 나온다).
- `calc_table`의 도구 후보 단계에서 메가 폼(`pokemon` 테이블의 메가 여부)이면 도구 축을 메가스톤 하나로 고정한다.

### F2 모래바람 특방 ×1.5
- 모래바람에서는 바위 타입의 특방이 ×1.5가 된다. 마기라스(모래날림)는 날씨를 스스로 만든다. 지금은 "계산하지 않은 특수 상황: 날씨"로 참고용 처리한다.
- F1 규칙대로 날씨 있음/없음 두 경우를 보인다. 날씨 체크박스와 특성(모래날림·가뭄 등)에서 자동으로 켠다. 쾌청(가뭄·메가리자몽Y)의 불꽃 ×1.5와 물 ×0.5도 같은 자리에서 다룬다. 범위는 TODOS S2(체크박스 계산 확장)와 겹친다.

### F4 포켓몬 검색에 메가 폼이 안 나옴
- "한카리아스"를 검색하면 메가한카리아스Z가 나오는데, "리자몽"을 검색하면 메가리자몽X/Y가 나오지 않는다(R2). 그래서 R1은 일반 리자몽으로 계산됐다.
- **사용자 의견:** "추가 별칭을 추가하기엔 부담이 있다." → 별칭을 늘리지 말고 검색을 고친다. 종 이름으로 검색하면 그 종의 모든 폼이 나오게 한다(`server/app.py` `_pokemon`의 species 조건). 메가리자몽X/Y의 species 값이 다르게 들어가 있는지부터 확인한다.

### F7 스피드 질문에서 내 도구가 자동 고정
- "내가 더 빠를 텐데 메가리자몽Y가 먼저 움직였어"(R7). 내 한카리아스의 도구가 통계 1위인 구애스카프로 가정돼서 결과가 이상해졌다.
- 사용자 설명: 고집 S32 한카리아스는 S32 겁쟁이 메가리자몽Y에게 추월당한다. 이것이 정답이다.
- 스피드 질문에서는 F1대로 상대 최고 스피드부터 비교한다. 내 도구를 통계에서 가정하면 화면에 가정이라고 드러내고, "도구 없음"과 함께 계산한다.
