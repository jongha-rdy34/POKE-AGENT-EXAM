# 실험 전 상태 (2026-11-27, 클라우드 세션)

로컬 노트북(Orca)에서 실험을 시작하기 전 최신 상태다. `HANDOFF-claude.md`·`HANDOFF-codex.md`보다 이 문서가 우선한다.

## 1. 정상 구동 확인 (`scripts/smoke.py`, 결과 `runs/smoke-20261127-032853/`)
[측정] 시나리오 S2~S5 입력을 화면 대신 API로 한 번씩 보냈다. 앱 코드는 고치지 않았다.

| 앱 | 결과 |
|---|---|
| A | 문장 읽기 4건 모두 HTTP 200(2~6초). 복기 S2·S3·S5 모두 결과까지 나옴. S4 없는 이름은 누락 칸(`my_form_key`, `move_key`)으로, 면역 조합은 누락 칸(`actual`)으로 응답. 빈 입력은 422 |
| B | S3(대면 판단)는 `ok`. S4 없는 이름은 후보를 제시하는 `ask`. **S2·S4 빈 팀·S4 5마리는 `UPSTREAM_ERROR`** |

**[측정] B의 `UPSTREAM_ERROR` 원인은 Gemini 무료 한도다.** 같은 시각 직접 호출한 결과가 HTTP 429였고, 한도 항목은 `GenerateRequestsPerDayPerProjectPerModel-FreeTier`, **limit=20**이었다(모델 표기 `gemini-3.6-flash`, 다음 초기화까지 약 4.5시간). 외부 데이터 API 문제가 아니다. Windows 세션이 본 같은 오류도 이 한도였을 가능성이 높다[해석].
- B는 LLM 오류를 모두 `UPSTREAM_ERROR`(LLM 서버가 정상 응답하지 않음)로 묶어 보여 준다(`backend/app/agent/llm.py`). 앱 동작이므로 고치지 않고 기록만 한다.
- 같은 날 앞서 S2가 정상 동작한 기록이 있다(선출·스피드·데미지까지, 약 26초).
- S5가 "내 포켓몬을 알려주세요"로 되물은 것은 같은 대화의 S2가 실패해 팀이 기억되지 않았기 때문으로 보인다[해석]. 한도가 남은 상태에서 다시 확인한다.

## 2. 한도 계획 [해석: 아래 호출 수는 추정]
- 무료 플랜: **프로젝트당·모델당 하루 20회.** 같은 프로젝트에서 키를 여러 개 만들어도 한도를 나눠 쓴다(한도 항목 이름이 PerProject).
- 실험 1회 예상 호출: A 문장 읽기 4회, B 요청 6회 × 내부 2~4회(12~24회), Gemini 판정 12회(+재요청). 합계 약 30~40회 → **무료로는 이틀 이상.**
- 줄이는 방법(적용됨: `scenarios.yaml` v2 `llm_call_policy`): 시나리오마다 앱 LLM 호출은 한 번만 하고, 같은 화면을 390×844로 바꿔 모바일 캡처를 얻는다.
- 판정 모델과 앱 모델의 한도는 모델별로 따로 센다. `gemini-3.5-flash` 요청이 `gemini-3.6-flash` 한도로 기록됐으므로 두 이름은 한도를 같이 쓸 수 있다.

## 3. 바뀐 파일
- `scenarios/scenarios.yaml` v2: YAML 파싱 오류(S3 B) 수정, **S3 A 문장에 기술 "지옥찌르기" 추가**(기술이 없으면 A가 계산을 시작하지 않음), B의 S3·S5 입력 문장 명시, 메가스톤 "없음" 명시. S3 문장 변경은 사용자 최종 확인이 필요하다.
- `scripts/serve.py`: Windows·macOS·Linux 공통 실행기. `judge-eval/.env`를 읽어 두 앱을 환경변수로만 설정해 띄운다(B의 `CACHE_DIR`은 절대경로). `python scripts/serve.py --check`.
- `scripts/smoke.py`: 위 점검. LLM 호출이 들어가므로 한도가 남았을 때만 돌린다. `--only A|B`, `--gap 초`.
- `.env.example`: `VENV_A`, `VENV_B`(가상환경 경로)를 추가로 읽는다. Windows 예: `VENV_A=C:\Users\<이름>\AppData\Local\POKE-AGENT-EXAM\venvs\A`.

## 4. 로컬 작업 트리와 합칠 때
Windows 세션이 같은 파일(`scenarios.yaml`, `HANDOFF-claude.md`, `.gitignore`)을 로컬에서 고쳤다. 그 브랜치를 push하기 전에 이 브랜치를 받아 합친다. `scenarios.yaml`은 이 브랜치의 v2를 쓴다(인용부호 수정 포함). `captures/`는 두 세션이 동시에 쓴 결과라 쓰지 않고 다시 받는다.
